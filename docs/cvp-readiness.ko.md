# CVP 개인 신청 준비 상태

기준일: **2026-10-13, Asia/Seoul**. 이 문서는 신청 준비 자료이며, 승인·제출 완료
또는 보안 요구 사항 준수를 증명하지 않습니다.

## 현재 판단

개인으로 신청할 수 있는 범위는 **유료 플랜의 Defense Access**입니다.
Red Team Access와 Specialized Access는 현재 조직 대상입니다.
[공식 도움말](https://support.claude.com/en/articles/14604842-cyber-verification-program)
기준이며, 아래의 계정·실적 확인이 아직 필요합니다.

사용자가 확인한 사실은 개인 신청자이고 GitHub 계정을 연결했으며, 공개된 보안
연구나 오픈소스 연구 실적이 없다는 것입니다. 연결된 공개 프로필은
[lejw9910-svg](https://github.com/lejw9910-svg)입니다. GitHub 연결은 CVP 본인 확인,
프로젝트 공개, 취약점 제보 실적을 대신하지 않습니다.
[2026년 10월 6일 발표](https://www.anthropic.com/news/cyber-verification-program)는
취약점 제보 실적이 있는 개인 연구자를 적격 사례로 설명합니다. 따라서 실적 부재는
중요한 근거 부족입니다. 다만 이를 모든 개인의 신청을 금지하는 명시적 규칙으로
바꾸어 해석하지 않습니다. 저장소의 완성도나 테스트 점수로 승인 확률을 계산할
수도 없습니다.

## 준비된 자료와 아직 없는 근거

| 항목 | 현재 상태 | 필요한 조치 |
| --- | --- | --- |
| 로컬 연구 도구와 합성 취약점 실습 | 저장소에서 확인 가능 | 실제 코드와 보고서를 같은 리비전으로 검토 |
| 검증·변이 벤치마크 결과 | 로컬 실행 근거로만 사용 | 보고서의 실패·오류·한계까지 확인 |
| 공개 연구 실적, CVE, 버그바운티, 고객 경력 | 제시할 실적 없음 | 없는 경력을 만들지 말고 그대로 기재 |
| 실제 Claude 실험·차단 사례 | 기록 없음 | 향후 허용된 실험을 했다면 원문과 조건을 정확히 기록 |
| 유료 Claude 플랜 | 확인되지 않음 | 본인 계정에서 확인 |
| CVP 본인 확인·신청·승인 | 이 작업에서 수행하지 않음 | 공식 포털에서 본인이 진행 |
| IdP 로그인·MFA·자격 증명 관리 | 확인되지 않음 | 실제 설정을 점검한 후에만 확인 서약 |

영문 [신청 초안](cvp-application.md)은 기존 성과와 앞으로의 계획을 구분합니다.
[검증 보고서](../reports/application/verification.json)와
[벤치마크 보고서](../reports/application/benchmark.json)는 작은 합성 사례에서의
도구 동작을 보여 주며, 실제 취약점 발견이나 Claude 성능 평가를 뜻하지 않습니다.
실제 저장소 URL은 공개 또는 확인 후에만 추가합니다.

현재 로컬 실행에서 Python 3.12.14로 **테스트 109개**가 통과했습니다. 네 실습의
검증 사례는 **총 44개(공격 9개, 정상 동작 회귀 35개)**입니다. 선별된 벤치마크는
정상 패치 **4/4개를 수용**, 잘못된 후보 **13/13개를 거부**했으며, 해당 17회 평가에서
잘못된 수용·거부, 실행 오류, 결론 불가 결과는 0개입니다. 증거 묶음의 **26개 파일**이
내부 체크섬 검사를 통과했습니다. 이는 정해진 합성 사례의 결과일 뿐, 실제 환경의
탐지율이나 승인 가능성을 뜻하지 않으며 GitHub에서 CI를 실행했다는 증거도 아닙니다.
[실행 요약](../reports/application/summary.json)과
[테스트 기록](../reports/application/tests.txt)에서 확인할 수 있습니다.

[역직렬화 사례 연구](case-studies/false-safe-deserialization.md)는 이 도구 자체의
검증 약점을 다룹니다. 위험한 재구성을 수행한 뒤 거부 응답만 반환하는 후보는 응답만
비교하면 통과하지만, 현재의 독립 감사 이벤트 관찰에서는 거부됩니다. 같은 관측값에
대한 판정 방식 비교이며, 과거 실험이나 Claude의 발견을 만들어 낸 것이 아닙니다.

## 신청 전 체크리스트

- [ ] 개인 신청에 필요한 유료 플랜을 확인한다.
- [ ] Google 또는 동등한 IdP를 통한 로그인을 확인하고, 접근 권한 부여 시점부터
  MFA가 활성화되어 있도록 한다.
- [ ] **2026-12-15까지** 보안 키·패스키·스마트카드/PIV 방식의 피싱 저항 MFA로
  전환하고 이메일 매직 링크를 사용하지 않는다. SMS, 음성, 이메일 코드, 인증 앱
  코드, 푸시 승인은 이 기준을 충족하지 않는다.
- [ ] 같은 기한부터 모델 접근에 정적·장기 자격 증명/API 키를 사용하지 않는다.
  Claude의 대화형 화면은 OAuth, 제공되는 프로그램 방식의 워크로드는 WIF를
  사용한다. 이 저장소는 API 키를 요구하거나 실시간 Claude 호출을 하지 않는다.
- [ ] 기한 전 임시 API 키를 사용하는 경우 개인용 키 하나만 허용되는 조건을
  확인한다. 비밀번호 관리자나 로컬 비밀 저장소에 보관하고, 공유·소스 포함 없이
  최소 7일마다 교체해야 한다. 현재 그런 키를 사용한다고 가정하지 않는다.
- [ ] 접근 권한을 혼자만 사용하고 계정·세션·프록시를 통해 타인에게 공유하지 않는다.
- [ ] 개인 CVP 트래픽은 보관·모니터링되며 **ZDR은 제공되지 않음**을 이해한다.
  비밀, 개인정보, 신분증, 실제 고객 데이터를 프롬프트나 저장소에 넣지 않는다.
- [ ] 침해 또는 오용 의심은 72시간 이내, 보안 사고는 24시간 이내 보고해야 함을
  확인한다. Anthropic이 알린 오용은 48시간 이내 조사하고, 오용 문의에는 7일
  이내 응답하는 절차를 준비한다.
- [ ] 고객 코드 분석 서비스 등 CVP를 이용한 외부 고객용 제품·서비스에는 별도
  신청과 승인이 필요함을 확인한다. 개인 신청서를 그러한 승인으로 취급하지 않는다.
- [ ] 신분증과 민감한 계정 증빙은 공식 포털이나 지정된 안전한 채널에만 제공한다.
  이 공개 가능한 저장소에는 넣지 않는다.
- [ ] 신청 직전에 공식 요구 사항을 다시 읽고 실제 충족한 통제만 서약한다.

계정 통제의 근거와 미확인 항목은 [보안 통제 문서](security-controls.md)에 구분되어
있습니다. 위 요구 사항의 출처는
[공식 보안 요구 사항](https://support.claude.com/en/articles/17202708-cyber-verification-program-security-requirements)이며,
모든 공식 출처의 확인일은 2026-10-13 (Asia/Seoul)입니다.

## CVP 필요성은 아직 가설

일반 Claude에서도 보안 코드 검토, 알려진 문제 수정, 소유한 소스의 취약점 탐색을
할 수 있습니다. 이 프로젝트가 제안하는 CVP 활용은 허가된 로컬 재현을 바탕으로
패치가 공격 동작을 막는지 검증하는 단계입니다. 공식 도움말은 exploit validation이
차단될 수 있다고 설명하지만, 현재 이 프로젝트에서 실제 차단된 증거는 없습니다.
필요성을 과장하거나 차단 사례를 만들어 내지 않습니다.

다음 30일은 [연구 계획](research-plan.md)에 따라 재현성과 정상 동작 검증을
강화하고, 가능한 범위에서 독립적인 검토를 받는 기간으로 삼습니다. 실적이 생기면
실제로 수행한 내용만 추가합니다. 신청서는
[공식 Verification Portal](https://portal.anthropic.com/programs)에서 직접 제출하며,
이 자료 작성 과정에서는 외부 전송이나 신청 제출을 하지 않았습니다.
